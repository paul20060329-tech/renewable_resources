# 绿循智审 - 再生金属合规校验平台

## 本地运行

首次运行：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --index-url https://pypi.org/simple -r requirements.txt
python app.py
```

后续运行只需：

```powershell
.\.venv\Scripts\Activate.ps1
python app.py
```

打开 `http://127.0.0.1:5000`。

## 重新生成演示数据

```powershell
python simulate/regenerate_demo_data.py
```

会基于 `Data/再生资源公司收购合规台账模板.xlsx` 重新生成 100 条全虚拟业务（90% 自然人 / 10% 公司，无任何真实姓名或地名），覆盖：

- 自然人/公司两种主体；
- 风险 / 审批 / 已付款三种业务状态；
- 时间顺序：`过磅 < 质检 < 入库 < 付款`；
- 数量顺序：`过磅净重 - 质检扣杂数量 = 入库数量`。

## 部署 Render

1. 将项目推送至 GitHub。
2. 在 Render 选择 **New +** → **Blueprint**，连接该仓库。
3. Render 会读取 `render.yaml` 并自动安装、启动。
4. 免费实例休眠后首次访问会有短暂冷启动；比赛正式使用建议本地运行或使用付费实例。
5. 在 Render 控制台的 **Environment** 中手动填写两个变量：
   - `DATABASE_URL`：Neon PostgreSQL 连接串（用于访问审计日志持久化）。
   - `SYSTEM_ADMIN_PASSWORD`：审计后台 `/system_admin` 的管理员密钥。

## 访问审计后台（/system_admin）

独立于业务系统的管理员入口，用于查看访客真实 IP、访问时间与登录用户。

- **访问地址**：`https://<你的域名>/system_admin`
- **鉴权**：独立密码（环境变量 `SYSTEM_ADMIN_PASSWORD`），与业务账号体系完全隔离。
- **记录内容**：访问时间（UTC）、真实访客 IP（解析 `X-Forwarded-For`）、登录用户与角色、请求方法、请求地址、状态码、User-Agent。
- **存储**：独立数据库，不写入业务库 `greenloop.db`。配置 `DATABASE_URL` 时使用 Neon PostgreSQL（重启不丢）；未配置时退化为本地 `access_log.db`。
- **功能**：KPI 概览、近 N 天访问趋势、访问最多的 IP、最活跃用户、最近登录记录；支持按 IP / 用户 / 关键词 / 日期筛选与分页。
- **只读接口**：`GET /system_admin/api/logs`（需先登录后台），便于后续导出或对接。

> 说明：IP 归属地精确到城市需接入离线库或付费 API。当前仅做本地判断（公网 / 内网 / 本机），不产生外部请求，避免拖慢主站。

## 账号与权限

| 账号           | 密码       | 角色       | 默认权限                                                    |
| -------------- | ---------- | ---------- | ----------------------------------------------------------- |
| `finance`    | `123456` | 财务负责人 | 数据总览、付款审批、合规台账                                |
| `accounting` | `123456` | 会计       | 数据总览、单据导入、核验中心、合规台账                      |
| `cashier`    | `123456` | 出纳       | 数据总览、付款中心、合规台账                                |
| `admin`      | `123456` | 后台管理员 | 全部权限                                                    |

- 财务负责人：金额达到或超过 5 万元的业务会出现在「付款审批」；不允许修改过磅单或质检单，只能查看和驳回。
- 出纳：只能确认「付款中心」的付款；≤ 5 万元且规则全部通过的业务会自动出现，≥ 5 万元须由财务负责人先审批。
- 会计：负责导入单据并在「核验中心」核对。
- 后台管理员：拥有全部权限，包括修改单据、重新提交。

界面侧只渲染当前角色有权限的板块，使用 Flask + Jinja2 的 `data-permission` 标记和前端 `applyPermissions()` 双重控制。

## 如何实验

1. 登录后进入「单据导入」，点击「下载标准 Excel 模板」。模板包含「过磅单」「质检单」「入库单」三个工作表：
   - 过磅单：包含「收款户名 / 银行卡号 / 开户行」，已移除微信付款码和溯源码；
   - 质检单：包含完整的扣杂、等级、计价字段；
   - 入库单：用于校验数量与时间顺序。
2. 也可以使用 `Data/再生资源公司收购合规台账模板.xlsx` 作为 59 列合规台账模板，保持第三行字段名不变；可重新生成 100 条虚拟数据来测试：`python simulate/regenerate_demo_data.py`。
3. 上传模板后系统会写入 SQLite 台账，并自动执行 9 项规则。数量规则为「过磅净重 - 质检扣杂数量 = 入库数量」，时间规则为「过磅时间 < 质检时间 < 入库时间 < 付款时间」。
4. 下载模板后系统在 `local_templates` 保存本地副本；编辑后保存 Excel，平台轮询会自动同步，也可以点击「同步本地模板」立即更新。
5. 到「核验中心」查看规则矩阵与每条规则的执行依据。
6. 规则全部通过且 ≤ 5 万的记录自动进入「付款中心」（出纳看到）；≥ 5 万的进入「付款审批」，由财务负责人审批后再进入付款中心。
7. 「风险业务」可一键驳回（不论金额），驳回后由后台管理员重新补件提交。驳回历史会完整记录在合规台账附件中，包括「第 N 次驳回」、驳回意见、原始单据与新版单据。
8. 「付款中心」以「前 4 + 掩码 + 后 4」形式展示收款虚拟银行卡号；点击小眼睛可切换完整号码。系统只记录付款确认，不会发起真实转账。
9. 「合规台账」只展示规则全部通过且已全付的业务；点开任何一条记录都能展开附件，查看驳回历史、原始单据和新版单据。
10. 后台管理可一键恢复初始演示数据（含 100 条全虚拟业务、已付款、风险和审批示例）。

## 数据管理

本地业务数据保存在项目根目录的 `greenloop.db`。比赛演示如需恢复初始数据，在停止服务后删除这个文件，再重新运行 `python app.py`。
